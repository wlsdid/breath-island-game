## Windows 실행 확인과 발견 사항

첫 Windows 빌드가 실제 저장 파일을 읽고 한국어 HUD를 표시했으며, 시작 로그에서 게임 예외는 발생하지 않았다. 이때 기존 저장 좌표가 섬 밖의 y=-464 부근에 있어 계속 낙하하는 진행 차단 문제를 발견했다.

`PlayerPositionSystem`으로 정상 저장 좌표는 유지하고 y < -5인 위치만 안전한 해안으로 복구하도록 수정했다. 복구 시 자원은 차감하지 않는다. 관련 회귀 테스트를 추가한 뒤 전체 테스트와 Windows 빌드를 다시 통과했다.

첫 실행 검증 전후 실제 저장 파일 2개의 해시가 같음을 확인했다. 테스트용 게임 프로세스는 자동 저장 없이 종료했다. 최종 수정본의 별도 Windows 화면 자동화 재실행은 사용자의 물리 Escape 입력으로 중단되었으며, 이후 컴퓨터 조작은 수행하지 않았다. 최종 수정본의 실제 Game View 렌더링과 부트스트랩은 Play Mode 테스트로 검증했다. 실제 게임패드 장치를 사용한 수동 검사는 수행하지 않았다.

## 실행 방법 및 결과 파일

```powershell
.\Build-BreathIsland.ps1
```

- `Builds/localization-setup.log`
- `Builds/editmode-results.xml`, `Builds/editmode-tests.log`
- `Builds/playmode-results.xml`, `Builds/playmode-tests.log`
- `Builds/build.log`, `Builds/Windows/BreathIsland.exe`

Play Mode HUD 테스트에는 실제 Game View가 필요하므로 `-batchmode`를 사용하지 않는다. 최초 배치 실행에서 HUD 테스트가 실패한 원인은 OnGUI가 호출되지 않았기 때문이며, 렌더링 검증을 생략하지 않고 실행 방식을 수정했다.

## 후속 Windows 플레이 확인

최종 빌드를 다시 실행해 기존 낙하 저장에서 해안·부두·플레이어가 정상 표시되는 것을 확인했다. 마우스 이동에 따른 카메라 회전과 도움말 버튼 클릭도 동작했다. 해당 실행의 Player.log에는 게임 예외가 없었다.

화면 자동화의 W/L/F9/Escape 키 입력은 게임 상태에 반영되지 않았다. 사용자가 실제 L키 입력으로 영어 전환이 동작함을 확인하여 자동화 입력 전달의 한계로 구분했다. 사용자의 실제 F9/F 입력으로 테스트 슬롯 불러오기와 낚시 준비 진입을 확인했다. 자동화 던지기로 시간 증가·미끼 소모·입질을 확인했으나 장력이 오르는 동안 화면 확인 지연이 있어 실제 낚시는 사용자 조작으로 진행했다. 사용자가 게임패드 미연결을 확인하여 실물 패드 검증은 수행하지 않았다.

첫 후속 검증 전에 기존 저장 2개를 백업하고 테스트용 수동 슬롯을 준비했다. 첫 후속 검증 종료 후 원본을 바이트 단위로 복원하고 해시 일치를 확인했다. 백업, 테스트 데이터와 실행 로그는 Git에서 제외된 `Builds/ManualQA`에 보존했다. 제품 코드와 기존 자동 테스트 결과는 변경하지 않았다.

두 번째 후속 검증은 별도 원본 백업과 테스트 슬롯으로 진행했다(`Builds/ManualQA2`). 사용자 조작 후 구름복어 발견·포획 1회와 탐험 복귀를 자동 저장으로 확인했다. 이어 조선소 1단계 복구, 코인 72→12, 재료 4→1, 보트·산호초 항로 해금을 확인했다. F5 수동 저장과 자동 저장의 진행 데이터가 일치했고, 위치 x=0/z=23, 포획 기록, 남은 미끼 5가 보존됐다.

사용자가 직접 이동·대화 후 나리 관계 1.25를 확인했다. 자동 저장과 수동 슬롯 1 모두 같은 관계·시설·인벤토리를 보존했고 위치는 나리 근처 x=-5.734/z=10.755로 갱신됐다. 사용자는 종료·재실행 후 진행 유지와 슬롯 2 저장·불러오기 정상 동작을 확인했다. 슬롯 2의 실제 JSON도 포획·시설·관계 진행을 보존했다.

별도 슬롯 3의 포식자 준비 데이터로 사용자가 전투 승리를 확인했다. 자동 저장에는 breaker 발견, 포획 수 2→3, 미끼 8→7이 반영됐다. 이 전투 검증은 핵심 루프 진행 저장과 분리했으며, 검증 시점별 JSON 사본을 `Builds/ManualQA2/core-loop` 및 `predator-win`에 보관했다.

슬롯 3의 준비 데이터를 다시 불러와 사용자가 포식자 패배 정상 동작을 확인했다. 패배 직후 자동 저장은 해안 (0, 1.2, 8), 미끼 6(캐스팅 1개와 패배 1개 소모), 포획 수 2, 발견 목록 비어 있음을 보여 보상 없이 복귀하는 기존 규칙을 확인했다. 이후 사용자가 슬롯 3 저장·불러오기와 게임 종료를 완료했다. 슬롯 3 JSON에도 패배 후 미끼·포획 수가 보존됐다.

게임 종료 후 테스트 저장을 `Builds/ManualQA2/result-saves`에 보관하고, 기존 원본 저장 2개를 복원하여 두 파일 모두 백업과 SHA-256 해시가 일치함을 확인했다. 최종 실행 로그는 `Builds/ManualQA2/player-final.log`에 보존했다. 이번 후속 작업은 검증 기록만 변경했으며, 제품 코드·밸런스·콘텐츠와 앞서 통과한 테스트·빌드는 그대로다. 실물 게임패드는 미연결로 검증하지 않았다.
