# 디자인·조작 개편 진행 기록

## 목표와 우선순위

신규 의뢰보다 기존 플레이의 외관과 조작 품질을 먼저 개선한다. 기존 저장, 아이템 ID, 보상량, 사용자 설정과 design asset 원본은 보존한다.

1. 캐릭터 접지와 이동 속도, 제공 에셋의 점프 동작.
2. 캐릭터·집·가구 비율, 재질·조명·배치의 실제 화면 개선.
3. 기본 실내 20×20 확장. 직사각형 등 다른 형태를 작성할 수 있도록 실내 경계·표현·배치 규칙을 공통 정의에서 읽는다. 기존 가구 좌표는 유지한다.
4. 인벤토리 슬롯 자유 선택·드래그 이동·교환·정리. 기존 수량의 단일 원천을 유지하고 임의의 용량·무게 규칙을 추가하지 않는다.
5. 채집 시간/횟수와 진행·타격 피드백. 보상량과 해금 집계는 유지한다.
6. 기능 묶음 완성 후 전체 테스트·Windows Mono 빌드·문서와 이번 변경만 커밋.

## 사용자 확정값 (2026-10-04)

- 이동 속도: 기존 5.2m/s의 55%, 즉 2.86m/s.
- 기본 실내: 20×20. 직사각형 등 다양한 모양도 지원하는 구조.
- 채집 시간·횟수: 미정. 앞서 제시한 3회·4회·1초는 승인되지 않았으므로 적용하지 않는다.
- 실내 다른 형태의 구체 치수/선택 방식: 미정. 기본 실내 확장과 형태 정의 분리를 먼저 진행한다.

## 진행

- 시작 Git 상태: AddressableAssetSettings, LocalizationSettings, PackageManagerSettings의 기존 변경과 미추적 design asset 폴더. 이번 변경에 임의로 포함하지 않는다.
- 기존 ModelPresentation은 SkinnedMeshRenderer의 애니메이션 여유 bounds를 크기·바닥 정렬에 사용했다. 실제 메시 기반으로 교체했다. 측정 결과 Idle의 바닥 차이 약 0.082m → 약 0.0003m(캐릭터 원점 기준). 실제 지형 위 접지는 별도 Play Mode 테스트로 확인한다.
- 제공된 Rig_Medium_MovementBasic.fbx에서 Jump_Start, Jump_Idle, Jump_Land 및 전체 점프 클립 확인. 새 외부 에셋 다운로드 없이 기존 캐릭터 Generic 리그에 연결한다.
- 탐험/실내 Space 점프, 메뉴 입력 차단. 탐험 낚시 시작은 F, 낚시 중 Space 감기는 유지한다. 패드는 기존 E 대응 버튼과 충돌하지 않는 북쪽 버튼에 점프를 연결하지만 실물 검증은 별도다.
- 이후 실내 확장·인벤토리·채집·전체 디자인 개선은 아직 완료되지 않았다.

## 완료 증거

각 기능의 규칙 테스트와 실제 렌더링 결과를 구분한다. Builds/PresentationUpgrade 아래 측정 로그·테스트 결과를 기록한다. 컴파일 성공만으로 Windows 플레이나 디자인 완료를 주장하지 않는다. 최종 결과는 VALIDATION.md에도 반영한다.

### 1차 기능 검증

- CharacterLocomotionTests 2/2 통과: 실제 스킨 메시 발바닥과 바닥 간격, 승인된 이동 속도, 점프 높이·착지·공중 재점프 방지·메뉴 및 닫기 입력 차단.
- 최초 테스트는 고정 프레임 대기와 입력의 수동 갱신 때문에 실패했다. 실제 시간 대기 및 정상 Input System 프레임 전달로 수정한 결과가 `Builds/PresentationUpgrade/locomotion-fixed.xml`이다.
- 아직 기존 전체 테스트, 실제 야외·실내 렌더링과 수정본 Windows 빌드를 실행하지 않았다. 현재 Builds/Windows 실행 파일에는 이번 변경이 반영되지 않았다.

### 2차 실내 확장

- 실제 RoomLayoutDefinition 에셋(HomeDefault)에서 기본 폭·깊이 20×20, 기존 출입 위치 (4,1), 출입구 예약 영역을 읽는다. 가구 좌표·재고·저장 버전은 변경하지 않는다.
- 배치·이동 경계, 실내 프리팹 바닥과 벽, 카메라가 같은 치수를 사용한다. 직사각형 폭·깊이 독립 검사를 추가했다. 추가 형태의 실제 치수·선택 방식은 사용자 답변 대기 중이다.
- 격자는 8×8 보기를 유지하면서 방향 버튼으로 다른 구역에 접근한다. 작은 20×20 버튼을 한 패널에 압축하지 않는다.
- 평상시 카메라는 고정 각도로 플레이어를 따라가고, 꾸미기/가방은 전체 방 시점을 사용한다. 확대 화면에서 가리는 전경 문틀을 낮은 문턱으로 변경했다.
- 실내 확장 규칙 4개 중 최초 출입구 예약 검사 실패: 수기 Rect 직렬화에 serializedVersion이 빠진 원인을 수정하고 실패 항목 재통과(`room-rules-fixed.xml`). 나머지 3개 최초 통과(`room-rules.xml`).
- 실내 이동·벽·출입, 가구/마감 저장 Play Mode 2/2 통과(`room-play.xml`). 추가 끝쪽 가구 저장·복원과 카메라 모드 1/1 통과(`room-camera.xml`). 이 결과는 전체 테스트나 Windows 빌드 결과가 아니다.
- 화면은 Builds/HomeInteraction/expanded-*.png에서 검토한다. 기본 집 확장만 구현된 상태이며 추가 집 형태, 인벤토리 재정리와 채집 작업은 남아 있다.
- 문턱·연속 바닥 마감 수정 후 추가 Play Mode 1/1 통과(`room-visual.xml`). 재렌더링에서 전경 가림과 바닥의 작은 검은 반복 틈이 제거된 것을 확인했다. 전체 디자인 개선은 계속 진행한다.

### 3차 인벤토리 자유 정리

- 전체 가방 탭에 6×4 슬롯, 실제 마우스 드래그·빈칸 이동·자리 교환·종류별 정리를 연결했다. 기존 종류별 탭의 잠긴 무기 설명, 제작·장착·실내 마감은 유지한다.
- InventoryLayoutSystem은 저장의 inventory.slotOrder에 물건 ID 순서만 저장한다. 보유량은 기존 장비·자원·가구 상태에서 매번 읽으며 수량 복사본이나 새 용량 규칙은 없다. 24칸은 페이지 크기이며 아이템 종류가 늘어나면 페이지가 확장된다.
- v4의 선택적 필드를 추가했다. v1~v4의 누락 목록은 빈 배열로 초기화하며 기존 수량·필드를 보존한다. 읽기만으로 파일을 다시 쓰지 않는다.
- InventorySlotDrag는 UI 포인터·아이콘 표현만 처리한다. 저장 변경은 LayoutSystem 명령으로만 수행한다. 닫기·탭 변경·정리·드래그 종료는 임시 아이콘을 정리하고 필드 사용으로 이어지지 않는다.
- Edit Mode 6/6(`inventory-rules.xml`), Play Mode 2/2(`inventory-play.xml`) 통과. 가상 Mouse 장치의 실제 Input System 이벤트를 통해 이동·교환, 자동/수동 네 슬롯 복원·수량 보존, 닫기 취소와 기존 도구 꺼내기를 검증했다. Windows 실행 파일 직접 조작과는 구분한다.
- 한국어·영어 렌더링: Builds/VillageExpansion/satchel-drag-ko.png, satchel-drag-en.png. 기존 전체 화면 비율 검증과 Windows 빌드는 기능 묶음 완성 후 수행한다.
- 남은 작업: UI·환경 디자인 세부 품질, 추가 형태 결정 및 채집 수치/진행 표현, 최종 전체 회귀·빌드·문서/커밋.

### 4차 인벤토리 디자인

- 실제 게임 모델과 재질로 도구·무기·가구·채집 자원 아이콘 21종을 렌더링했다. 몸체의 가장 긴 축과 넓은 면을 기준으로 도구·무기 시점을 보정하여 활 등이 옆으로 눕거나 가늘게 사라지지 않게 했다.
- 수량은 아이콘과 분리된 종이 라벨에 표시한다. 원래의 제목/본문 서체, 천 탭·종이 버튼과 한국어·영어 문구를 유지한다.
- Resource Bits의 나무·돌 모델과 공용 텍스처·CC0 문서만 추가 선별했다. 원본 ZIP과 모델은 변경하지 않았으며 RESOURCE_ICON_SELECTION.json 및 라이선스 문서에 기록했다.
- 드래그·저장 회귀와 한·영 1280×720/1920×1080/2560×1080 렌더링 Play Mode 2/2 통과(`inventory-icons.xml`). 이미지에서 도구와 가구 표시·수량·영문 줄바꿈, 1920 한국어 가독성을 확인했다.
- 이후 아이콘 자체의 방향·여백을 보정하고 렌더 원본(활·도끼·소파)을 확인했다(`icon-framing.log`). 최종 화면은 전체 회귀 실행 때 다시 기록한다.
- 현재까지의 기능 묶음을 정리하고 전체 테스트·Windows 빌드로 이어갈 예정이며, 채집 및 추가 집 형태의 미정 항목은 완료로 간주하지 않는다.
- 2026-10-04 전체 Edit 81/81, 전체 Play 최초 28/29 후 입력 격리 수정/관련 UI 5/5 통과. Mono 빌드 122.3 MB 성공. 실행 파일 갱신 완료. Windows 시작 로그만 확인했고 화면 도구의 대상 불일치로 직접 조작은 하지 않았다. 자세한 범위와 미검증 항목은 VALIDATION.md 참조.

### 5차 채집 진행 구조 (수치 미확정)

- 도구 타격 횟수와 맨손 길게 누르기 시간을 콘텐츠 정의에서 읽는 구조를 추가했다. 실제 지점 에셋은 기존 1회/즉시 채집을 유지한다. 3회·1초는 복제한 테스트 데이터에서만 사용하며 확정 밸런스가 아니다.
- 완료 전에는 자원·누적 획득·채집 실적을 변경하지 않는다. 완료 후 기존 보상을 한 번만 지급하고 소진 처리·저장한다.
- 길게 누르기는 키를 놓거나 메뉴를 열거나 대상의 거리·방향에서 벗어나면 취소한다. 유효 타격 진행은 대상별로 유지하되 로드·휴식에서 초기화한다. 중간 진행은 저장하지 않는다.
- 탐험 HUD에 진행 막대, 한국어·영어 길게 누르기 안내를 연결했다. 실제 채집 수치와 추가 집 형태는 여전히 결정 대기 중이다.
